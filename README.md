# BOM 扫码质量监管系统（通用版）

基于 BOM + 总包订单 + 配件订单生成总包/子件标签，出货扫码做齐套校验的局域网系统。

## 两步上手（Windows）

把整个项目文件夹拷到服务器电脑后：

| 步骤 | 操作 | 说明 |
|------|------|------|
| ① 配置环境 | 双击 **`setup.cmd`** 或 **`一键配置环境.bat`** | 检查 Node.js（需 22.5+）、装依赖；结束后会停住等你按键，**不会一闪而过** |
| ② 开始运行 | 双击 **`start.bat`** 或 **`开始运行.bat`** | 启动服务并自动打开浏览器 |

推荐优先用 **`setup.cmd`** / **`start.bat`**（纯英文脚本，兼容性最好）。

启动成功后：

- 本机：http://127.0.0.1:3789
- 局域网其他电脑：http://服务器IP:3789

### 通用版说明（重要）

本版本**不再使用** `better-sqlite3` 原生模块，改为 **Node.js 内置 SQLite**。

- 不需要安装 Visual Studio / C++ 编译工具  
- 不需要为每个 Node 版本找预编译包  
- 只需安装官网 **Node.js 22.5+（Windows x64）**，再一键配置即可  

> 关闭「开始运行」窗口 = 停止服务。日常只需再点 **开始运行.bat**。

## 功能概览

- 上传 BOM 后自选母件列与母件值（同母件可多版本共存）
- 导入总包订单、配件订单（Excel），可保存列映射规则
- 订单先按自定义列关联总包与配件，再按料号匹配 BOM（不校验用量）
- 齐套数量在扫码时按已关联配件订单行判定
- 匹配成功可生成标签；标签模板支持表格、公式、唯一码；总包/配件可分开打印，适配 A4/标签纸；无订单也可自定义内容打印
- 扫码入库 + 扫码查单 + **计数扫码**；齐套后扫下一总包不误报缺漏
- **计数订单**：导入订单后可配置整除/余数等衍生列，指定识别列与目标数量列，扫码累计到达即提示满足并进入下一行
- 角色：导入打印 / 扫码入库 / 管理员；记录查询与 Excel 导出

## Linux / macOS

```bash
cd bom-scan-qc
npm install
npm start
```

需要 Node.js **22.5+**。改端口：`PORT=8080 npm start`

## 从旧版本升级

若以前安装失败（`better-sqlite3` / `node-gyp` / Visual Studio）：

1. 更新到本仓库最新代码  
2. **删除**项目里的 `node_modules`  
3. 再双击「一键配置环境.bat」  

旧数据库文件 `data/qc.db` 可继续使用。

## 常见问题

| 现象 | 处理 |
|------|------|
| `node -v` 正常，但提示未配置 / 环境未就绪 | 多半是**项目依赖没装**（只有 Node 不够）。请在项目目录双击「一键配置环境.bat」，或执行 `npm install`。若已是最新通用版，不要再找 `better-sqlite3` 文件夹 |
| 双击配置窗口一闪而过 | 请拉**最新**代码。启动器已改为同窗口 `call` + `pause`（不再用会失败的 `start /k` 重开窗口），脚本为纯 ASCII。请双击 **`setup.cmd`**；结束后应出现 `Press any key`，需按键才会关。若仍闪退，可能是杀毒/拦截，或未解压完整（确认同目录有 `setup-env-en.bat`、`package.json`） |
| 提示 Node 版本不够 | 安装 Node.js 22.5+（https://nodejs.org），重开脚本 |
| `EPERM` 删不掉 node_modules | 关闭占用程序/杀毒后手动删除再配置 |
| 端口被占用 | 关掉已打开的运行窗口 |
| 不要拷贝别人的 node_modules | 在本机重新「一键配置环境」 |
